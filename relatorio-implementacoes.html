Projeto Laravel 13

Relatório de implementações

Resumo das atualizações do ambiente Docker e das correções realizadas no fluxo de autenticação da API.

Data: 24 de novembro de 2026

Concluído e validado

1. Atualização do ambiente Docker

As configurações do PHP-FPM e do Compose foram alinhadas aos requisitos do Laravel 13, que exige PHP 8.3 ou superior.

  • Dockerfile: imagem atualizada para PHP 8.4 FPM, com Composer 2 e extensões PHP utilizadas pelo projeto.
  • Extensões habilitadas: bcmath, exif, gd, mbstring, oci8, pcntl, pdo_mysql, pdo_sqlite, xdebug e zip.
  • Usuário e grupo do container configurados por UID/GID, com valores padrão 1000, para reduzir problemas de permissões nos arquivos montados.
  • docker-compose.yml: serviços PHP-FPM e Nginx; aplicação publicada na porta 9090; Xdebug configurado na porta 9003.
  • Adicionado host.docker.internal via host-gateway para permitir a comunicação do Xdebug com o host em Linux.

2. Correção da criação de tokens

O erro Call to undefined method App\Models\User::createToken() acontecia porque o modelo de usuário não utilizava o trait fornecido pelo Laravel Sanctum.

  • Adicionado Laravel\Sanctum\HasApiTokens ao modelo User.
  • Com isso, o método createToken() usado no login pode emitir tokens de acesso pessoal.
  • O teste de login verifica a resposta HTTP 201 e a presença do token no JSON.

3. Resposta de autenticação para rotas da API

O erro Route [login] not defined surgia quando uma requisição não autenticada às rotas da API acionava o redirecionamento padrão do middleware para uma rota web inexistente.

  • Em bootstrap/app.php, o redirecionamento de convidados foi configurado para não gerar URL de login nas rotas api e api/*.
  • O tratamento existente de exceções para rotas da API retorna uma resposta JSON de não autenticado, com status HTTP 401.
  • O redirecionamento padrão para as demais rotas foi preservado.
  • O teste cobre uma requisição sem autenticação e sem cabeçalho Accept: application/json, confirmando que a API não tenta redirecionar.

As rotas atuais estão em routes/api.php; o grupo protegido utiliza o middleware auth:sanctum.

4. Testes e validações

  • Build da imagem Docker concluído com sucesso.
  • Configuração do Compose validada com docker compose config --quiet.
  • Imagem executada para confirmar PHP 8.4 e carregamento das extensões listadas acima.
  • Manifesto Composer validado.
  • Testes focados de autenticação: 2 testes passaram, com 5 asserções.
  • Verificação de formatação com Laravel Pint aprovada para os arquivos PHP alterados.
  • Verificação de whitespace com git diff --check aprovada.

Resultado: a imagem Docker atende à versão mínima de PHP do Laravel 13; o login pode criar tokens Sanctum; e requisições não autenticadas à API recebem 401 JSON em vez de falharem ao procurar a rota web login.
